# Эксперимент 02: MVP «ВК одного санузла» — сквозной контур на живой модели

**Дата:** 2026-07-18
**Статус:** завершён
**Этап плана:** этап 2 — MVP: ВК одного санузла по готовой АР

## Цель

Пройти полный цикл этапа 2 на реальном санузле учебной модели: чтение модели →
паспорт задачи → гидравлика → трассировка → создание труб в Revit → нормоконтроль
с цитатами → спецификация.

## Окружение

## Ход эксперимента

1. **Аналитик v0 (чтение модели).** Rooms в инженерной модели нет — приборы найдены
   фильтром по категории и кластеризованы по координатам. Выбран санузел квартиры
   на L2: унитаз, 2 умывальника, душ, стиральная машина (5 приборов, id в паспорте);
   у каждого прибора считаны MEP-коннекторы (точки/диаметры К1, В1, Т3), рядом найден
   существующий канализационный стояк Ду102 (id 1478851). Всё сведено в passport.json;
   недостающие исходные данные (U жителей, q_hr_u из табл. А.2) помечены
   «⚠️ задание инженера».
2. **Расчётчик v0.** По формулам (2), (3) СП 30: q_В1 = 0,327 л/с → Ду20 (v = 1,04 м/с);
   q_Т3 = 0,199 л/с → Ду15 (v = 1,13 м/с); стояк К1: qs = 1,927 л/с ≤ 3,58 л/с
   (табл. К.1) — проходит.
3. **Трассировщик v0.** Манхэттенские трассы: сборный К1 под полом по оси стояка
   с постоянным уклоном 0,02, отводы приборов с тем же уклоном; магистрали В1/Т3
   под потолком (+2700 от пола) с опусками к коннекторам. Итого 29 сегментов.
4. **Нормоконтроль v0.** Rule-based чек-лист (calc/normcheck): уклоны ≥ 1/d (п. 19.1),
   постоянство уклона сборного (п. 18.2), диаметры отводов/подводок ≥ табл. А.1,
   скорости ≤ 1,5 м/с (прил. И / п. 8.26), стояк по прил. К. **0 нарушений,
   23 проверки пройдены**, каждая строка с цитатой.
5. **Создание в Revit.** 29 труб созданы одной транзакцией через execute_revit_code
   (Pipe.Create; системы Sanitary / Domestic Cold Water / Domestic Hot Water,
   типы PVC-DWV и Copper), id 1738985–1739069.
6. **Верификация чтением обратно:** все 29 труб существуют, системы и диаметры верны,
   уклон коллектора по координатам концов = 122 мм / 6101 мм = 0,02.
7. **Спецификация v0** из параметров модели: К1 Ду110 — 6,13 м, Ду50 — 4,08 м;
   В1 Ду20 — 6,05 м, Ду15 — 14,92 м; Т3 Ду15 — 18,31 м
   ([specifikaciya.md](02-mvp-sanuzel/specifikaciya.md)).

## Результат

Полный контур «модель → паспорт → расчёт → трасса → Revit → нормоконтроль →
спецификация» пройден за одну сессию; чек-лист зелёный, трубы в модели.

Грабли по пути: `ElementId.IntegerValue` убран в Revit 2026 (использовать
`.Value`/`str`), конструктор `ElementId(int)` требует `Int64`, `execute_revit_code`
сам открывает транзакцию (свою создавать нельзя) — уже в docs/lessons.md.

## Ограничения v0 (осознанные)

- Фитинги и врезки не создаются — сегменты не соединены между собой и с приборами;
  коннекторы приборов заняты заводской обвязкой модели, наши трассы — параллельный
  «черновик» для сравнения.
- Диаметр отвода душа взят по табл. А.1 (Ду50), тогда как коннектор трапа в модели
  102 мм — правило «диаметр не меньше выпуска прибора» в чек-лист v1.
- Стены/проёмы не учитываются (трассы могут пересекать конструкции), clash detection
  не запускался.
- Высоты установки приборов не проверялись: семейства-подключения без геометрии бортов.

## Выводы

1. Связка «детерминированное ядро + LLM-оркестратор + MCP» работает end-to-end:
   расчёты и геометрия — код с тестами (73 зелёных), решения и protokol — сессия.
2. Паспорт задачи как JSON-контракт между ролями (аналитик → расчётчик →
   трассировщик → нормоконтролёр) — удачная граница; роли этапа 2 можно оформлять
   сабагентами поверх него (проба: .claude/agents/normokontroler.md).
3. Следующие шаги: фитинги/соединения (RoutingPreferences или готовые инструменты
   MCP), учёт стен из АР-подложки, clash detection с заводской обвязкой,
   переформулированные вопросы и высоты в чек-лист.
