# ИИ-проектирование разделов строительства (пилот: ВК)

Исследование и план создания системы, в которой ИИ-агенты проектируют отдельные разделы
строительного проекта (АР, КЖ, ЭОМ, ВК) в Revit / Renga / AutoCAD / IFC — по образцу
отраслевой системы «Норникеля», но силами небольшой команды.

## Главный вывод

**Да, это возможно — но не как «нажал кнопку и получил раздел ВК».**

Реалистичная и уже сегодня достижимая схема:

> **LLM-агенты управляют** процессом и интерпретируют ТЗ →
> **детерминированные алгоритмы считают** (трассировка труб, гидравлика, подбор диаметров) →
> **база знаний норм проверяет** каждый шаг (СП, ГОСТ) →
> **инженер утверждает** результат.

Это ровно та архитектура, что у «Норникеля»: там ИИ ускорил рутину на 80 %, но
«окончательное решение принимает инженер». Полностью автономного ИИ-проектировщика
не существует ни у кого — а вот система, снимающая 70–80 % рутины раздела ВК, собирается
из уже существующих open-source компонентов.

Ключевые факты, найденные в исследовании:

- **Claude уже умеет управлять Revit** — существует несколько open-source MCP-серверов,
  включая инструменты создания труб и MEP-систем; у Autodesk с 2026 г. есть официальный MCP-сервер.
- **Первое здание с ИИ-спроектированной электрикой уже построено** (Augmenta, школа в США):
  проектирование на 25 % быстрее, материалов на 15 % меньше.
- **Научный прототип «текст → BIM-модель» открыт** (Text2BIM, MIT-лицензия) — мультиагентная
  система с нормопроверщиком в контуре, мини-аналог подхода «Норникеля».
- **Наивный RAG на СП/ГОСТ не работает** — нужен агентный поиск и структурированные правила
  (эксперименты показывают на порядок меньше выдуманных ссылок на нормы).
- **Renga имеет открытый API с официальной поддержкой Python** — легальный российский путь.

## Структура репозитория и работа с Claude Code

Проект ведётся с Claude Code; инфраструктура настроена по
[лучшим практикам](https://code.claude.com/docs/ru/best-practices):

| Путь | Назначение |
|---|---|
| [CLAUDE.md](CLAUDE.md) | Контекст и правила проекта, загружается в каждую сессию |
| `.claude/rules/` | Модульные правила: нормативка, стиль документов, код (по типам файлов) |
| `.claude/skills/` | Команды: `/new-experiment`, `/check-docs`, `/status` |
| [experiments/](experiments/) | Журнал практических экспериментов (этап 0+) |
| [norms/](norms/) | Полные md-тексты СП ядра ВК (слой 3 базы знаний) |
| `rules/`, `calc/`, `tests/` | Слой 1 базы знаний: YAML-правила из таблиц СП + расчётный код с тестами |
| `norms_mcp/` | MCP-сервер поиска по norms/ (BM25 + полный текст пункта), регистрация в `.mcp.json` |
| [validation/](validation/) | Контрольные вопросы для проверки базы знаний |

Память между сессиями живёт в git: [docs/status.md](docs/status.md) импортируется в
CLAUDE.md автоматически, [docs/decisions.md](docs/decisions.md) и
[docs/lessons.md](docs/lessons.md) читаются по требованию.

## С чего начать прямо сейчас

Первый эксперимент занимает один вечер и не требует ни строчки своего кода:

1. Установить [pyRevit](https://github.com/pyrevitlabs/pyRevit) (бесплатно) на компьютер с Revit.
2. Установить MCP-сервер [Demolinator/revit-mcp-server](https://github.com/Demolinator/revit-mcp-server)
   (48 инструментов, включая `create_pipe` и `create_mep_system`).
3. Подключить его к Claude Desktop или Claude Code.
4. Попросить Claude: *«Открой модель, найди все санузлы на 2-м этаже и перечисли санприборы»* —
   и дальше по нарастающей.

Подробности — в [плане реализации](docs/03-plan-realizacii.md).
