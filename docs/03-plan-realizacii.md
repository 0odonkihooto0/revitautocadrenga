# План реализации: от первого эксперимента до MVP раздела ВК

Этапы построены так, что каждый даёт самостоятельный полезный результат, даже если
на нём остановиться. Оценки трудозатрат — для одного человека с опытом программирования,
работающего в свободное время; в скобках — при полной занятости.

## Этап 0. Проба связки «Claude ↔ САПР» (1–2 недели / 2–3 дня)

**Цель:** увидеть своими глазами, как LLM управляет Revit и Renga; понять ограничения.
Не требует своего кода.

Задачи:

1. **Revit-ветка** (на компьютере с Revit):
   - Установить [pyRevit](https://github.com/pyrevitlabs/pyRevit) (бесплатный, MIT).
   - Развернуть [Demolinator/revit-mcp-server](https://github.com/Demolinator/revit-mcp-server)
     (Python 3.11+, `uv sync`, включить pyRevit Routes на порту 48884) — 48 инструментов,
     включая `create_pipe`, `create_mep_system`, clash detection, спецификации.
     Альтернатива: [mcp-servers-for-revit](https://github.com/mcp-servers-for-revit/mcp-servers-for-revit) (монорепозиторий, C#).
   - Подключить к Claude Desktop или Claude Code (конфиг MCP-сервера).
   - Прогнать сценарии по нарастающей на учебной модели:
     «перечисли санприборы на этаже» → «создай трубу от точки А к Б» →
     «создай систему К1 и подключи приборы санузла 2.01» → «сделай спецификацию труб».
2. **Renga-ветка** (параллельно): скрипт на Python, подключающийся к Renga через COM
   (документированный сценарий Renga API), — прочитать модель, создать простой объект.
   Это разведка перед этапом 2.
3. Зафиксировать в `experiments/` репозитория: что сработало, что нет, скриншоты, выводы.

**Критерий готовности:** Claude по текстовой команде создаёт трубопровод в живой модели
Revit; из Python прочитаны объекты модели Renga.

## Этап 1. База знаний норм ВК (2–4 недели / 1–2 недели)

**Цель:** ИИ-справочник по нормам ВК, который отвечает с точными цитатами и не выдумывает
пункты. Самостоятельно полезен уже как «карманный нормоконтролёр».

Задачи:

1. Собрать тексты ядра нормативной базы (список в [01-issledovanie.md](01-issledovanie.md), §4):
   СП 30.13330.2020, СП 73.13330.2016, СП 10.13130.2020, ГОСТ 21.601-2011, ПП № 87.
   Конвертировать в структурированный Markdown с сохранением нумерации пунктов и таблиц.
2. Оцифровать 15–20 ключевых таблиц и формул СП 30.13330 в YAML/JSON + написать расчётный
   код (расходы по прил. А, уклоны, минимальные диаметры) с юнит-тестами по примерам
   из учебников/пособий.
3. Поднять MCP-сервер поиска по базе (BM25 + опционально эмбеддинги) с выдачей полного
   текста пункта. На самом старте можно обойтись Claude Projects (загрузить файлы норм),
   но своя база нужна для контроля качества и слоя правил.
4. Валидация: составить 30–50 контрольных вопросов с известными ответами
   («минимальный уклон К1 Ду50?», «где нельзя прокладывать канализацию?») и прогнать.
   Ориентир качества — из исследования §5: без агентного поиска модели массово
   галлюцинируют, с ним ошибки единичны.

**Критерий готовности:** ≥ 90 % контрольных вопросов — верный ответ с верной цитатой.

## Этап 2. MVP: ВК одного санузла по готовой АР (1–2 месяца / 3–4 недели)

**Цель:** система уровня L2–L3 на минимальном объекте — типовой санузел (унитаз, раковина,
ванна) в учебной АР-модели. Полный цикл: чтение АР → трассы → диаметры → спецификация.

Задачи:

1. Мультиагентный контур на Claude Agent SDK / Claude Code с сабагентами по ролям из
   [02-arhitektura.md](02-arhitektura.md) §3 (оркестратор, аналитик, компоновщик,
   расчётчик, нормоконтролёр, документатор). На этом масштабе «агент» = системный промпт
   + набор MCP-инструментов, без своей инфраструктуры.
2. Детерминированный трассировщик v0: подводки К1 от приборов к стояку с уклоном по слою
   правил; подводки В1/Т3. Геометрия помещения — из АР-модели через MCP; выход — вызовы
   `create_pipe`.
3. Гидравлика v0: расчётные расходы для набора приборов, подбор диаметров подводок
   и стояка по слою правил.
4. Нормоконтроль v0: rule-based чек-лист (уклоны, диаметры, высоты установки приборов)
   + отчёт с цитатами.
5. Спецификация v0: выборка труб/фитингов из модели в таблицу.
6. Сквозной прогон с протоколом решений; итерация до сходимости.

**Критерий готовности:** по команде «сделай ВК для санузла 2.01» система создаёт в Revit
корректные (по чек-листу нормоконтроля) трубопроводы В1/Т3/К1 и выдаёт спецификацию;
инженер тратит на проверку минуты, а не часы.

## Этап 3. Инженерная глубина (2–3 месяца)

- Масштаб «этаж → стояки → здание»: компоновка стояков, магистрали, ввод, водомерный узел.
- Полный гидравлический расчёт с требуемым напором и проверкой на насосную установку.
- Циркуляция ГВС.
- Спецификации по каталогам реальных производителей.
- Clash detection с другими разделами (готовые инструменты в revit-mcp-server).
- Пояснительная записка по составу ПП № 87 — сильная сторона LLM, у «Норникеля» именно
  текстовая часть вышла «без замечаний».

## Этап 4. Документация, платформы, другие разделы (далее)

- Оформление рабочей документации по ГОСТ 21.601: планы, аксонометрические схемы, узлы,
  штампы (через виды/листы Revit или экспорт в DWG через autocad-mcp).
- **renga-mcp**: MCP-обёртка Renga COM API (Python + FastMCP) — перенос пайплайна на
  российскую платформу; сам по себе продукт с открытой нишей.
- Нейтральное IFC-ядро (IfcOpenShell) для платформонезависимости.
- Тираж на следующий раздел — логичнее всего ЭОМ (мировой опыт самый зрелый) или ОВ
  (переиспользует трассировщик и гидравлику).

## Ресурсы

### Софт и лицензии

| Инструмент | Роль | Стоимость / лицензия |
|---|---|---|
| Claude Pro/Max (Claude Desktop + Claude Code) | мозг системы на этапах 0–2 | ~$20–100/мес |
| Claude API (Agent SDK) | мультиагентный контур с этапа 2 | по токенам; порядок $50–300/мес при активной разработке |
| pyRevit | мост в Revit | бесплатно (MIT) |
| revit-mcp / revit-mcp-server | MCP-инструменты Revit | бесплатно (MIT) |
| **Revit** | целевая платформа №1 | ⚠️ см. примечание ниже |
| Renga | целевая платформа №2 | коммерческая, продаётся в РФ; есть бесплатная версия для учебных целей |
| nanoCAD | 2D-документация | коммерческая, продаётся в РФ |
| IfcOpenShell + Bonsai (Blender) | бесплатное IFC-ядро | бесплатно (LGPL/GPL) |
| Python 3.11+, uv, git | обвязка | бесплатно |

**⚠️ Про Revit без лицензии — честно.** Autodesk ушёл из РФ и не продаёт новые лицензии;
без активации Revit легально не работает. Легальные пути: действующая лицензия
(если осталась у вас/работодателя), 30-дневный trial для экспериментов этапа 0,
образовательная лицензия (для учащихся). Использование пиратской копии — юридический риск,
на котором нельзя строить продукт. Поэтому архитектура (см. 02, §7) сознательно
мультиплатформенна: **долгосрочная ставка — Renga + IFC-стек**, Revit — как референсная
среда, пока доступна. Это же и ответ на вопрос «а если Revit отвалится»: ядро системы
от него не зависит.

### Железо

Обычная рабочая станция, на которой уже работает Revit/Renga, — достаточна.
GPU не нужен: LLM работает в облаке (Claude API). Локальные модели (Qwen и т.п.)
имеет смысл рассматривать только на этапах 3–4, если критична работа без интернета, —
тогда потребуется GPU от 24 ГБ VRAM, и качество будет ниже фронтирных моделей.

### Компетенции

| Роль | Зачем | Кто |
|---|---|---|
| Инженер ВК | правила, валидация, контрольные вопросы, приёмка | обязательно (вы/коллега) |
| Python-разработчик | MCP, трассировщик, расчёты, база знаний | обязательно |
| BIM-специалист | семейства, шаблоны Revit/Renga, стандарты моделей | желательно с этапа 2 |

Один человек, совмещающий инженера и разработчика, может дойти до конца этапа 2.

## Риски и ограничения

| Риск | Серьёзность | Смягчение |
|---|---|---|
| Галлюцинации на нормах | Высокая | Агентный поиск + обязательные цитаты + структурированные правила вместо «памяти» модели (этап 1); расчёты — только кодом |
| Юридическая ответственность | Высокая | Система позиционируется как инструмент инженера (L3), не как проектировщик; подпись и ответственность — у человека; протокол решений для проверяемости |
| Качество исходных АР-моделей | Средняя | Этап нормализации данных + явные вопросы инженеру при нехватке данных (шаг 2 пайплайна) |
| Доступность Claude API из РФ | Средняя | Работа через доступные каналы; архитектурно LLM-слой абстрагирован — заменим на другой API (GigaChat, YandexGPT) или локальную модель ценой качества |
| Лицензии Autodesk | Средняя | Мультиплатформенность: Renga + IFC-ядро (см. выше) |
| Стоимость токенов при больших моделях | Низкая | Кэширование контекста, передача агентам выжимок модели, а не всей модели; детерминированные шаги бесплатны |
| «Долина разочарования» (демо легко, продукт трудно) | Средняя | Этапная структура: каждый этап полезен сам по себе (справочник норм, автотрассировка санузла) |
