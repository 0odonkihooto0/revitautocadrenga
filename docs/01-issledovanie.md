# Исследование: может ли ИИ проектировать разделы строительства?

*Дата исследования: июль 2026. Пилотный раздел — ВК (водоснабжение и канализация).*

## 1. Разбор кейса «Норникеля»: что на самом деле стоит за новостью

Из пресс-релиза известно: система «продумывает проект от фундамента до кровли», обучена на
базе знаний с ГОСТами и СНиПами, запросы обрабатывают ИИ-агенты, «окончательное решение
принимает инженер». Результаты: задания на проектирование — на 83 % быстрее, цифровая модель —
на 80 % быстрее, документация — вдвое быстрее.

Если снять маркетинговый слой, технически это почти наверняка:

1. **База знаний (RAG + структурированные правила)** — корпоративные стандарты, ГОСТы и СП,
   превращённые в машиночитаемый вид, по которым LLM ищет и цитирует требования.
2. **Мультиагентная система** — не одна нейросеть, а набор специализированных агентов:
   один разбирает ТЗ, другой делает расчёты, третий строит модель через API BIM-системы,
   четвёртый проверяет результат на соответствие нормам, пятый формирует документацию.
3. **Интеграция с BIM через API** — агенты не «рисуют картинки», а вызывают функции
   BIM-платформы (создать стену, проложить трубу, сформировать спецификацию).
4. **Human-in-the-loop** — инженер остаётся точкой принятия решений; ИИ ускоряет рутину,
   а не заменяет ответственность.

Важное следствие: **ни один из этих компонентов не является секретной технологией.**
Каждый доступен в open-source или через публичные API. Разница между «Норникелем» и
энтузиастом — в объёме корпоративной базы знаний, количестве инженеров для проверки
и в деньгах на доводку. Но прототип того же класса собирается малыми силами.

Обратите внимание на формулировку результатов: быстрее всего ускорились *задания на
проектирование* (83 %) и *текстовая часть документации* («нет замечаний») — то, что LLM
делают лучше всего. Про то, что ИИ сам чертит рабочие чертежи КЖ, в релизе не сказано.
Это честная граница текущих возможностей, и она же — ориентир для нашего проекта.

## 2. Уровни автоматизации: где проходит граница возможного

Полезно мыслить уровнями, по аналогии с автопилотами:

| Уровень | Что делает ИИ | Статус на 2026 |
|---|---|---|
| **L0. Справочник** | Отвечает на вопросы по нормам («какой уклон у канализации Ду110?») с цитатами из СП | ✅ Работает уже сейчас (при агентном поиске, см. §5) |
| **L1. Ассистент в САПР** | Выполняет команды в Revit/Renga голосом/текстом: «выдели все трубы ГВС», «создай спецификацию» | ✅ Работает через MCP-серверы (см. §3) |
| **L2. Автоматизация подзадач** | Сам выполняет законченные куски: трассировка стояка, гидравлический расчёт, спецификация с подбором по каталогу | ✅/🟡 Достижимо: алгоритмы известны, нужна сборка (MagiCAD делает без ИИ, Augmenta — с ИИ) |
| **L3. Черновик раздела** | По АР-модели и ТЗ выдаёт черновик раздела ВК целиком; инженер правит и утверждает | 🟡 Передний край: Augmenta (электрика — уже в стройке, сантехника — альфа), «Норникель». **Цель этого проекта** |
| **L4. Автономный проектировщик** | Полный раздел со штампом без проверки человеком | ❌ Не существует и юридически невозможно (подпись ГИП, экспертиза) |

Вывод: целиться нужно в **L3 с опорой на L1–L2**, при этом L1 достижим за один вечер.

## 3. Обзор существующих решений

### 3.1. MCP-серверы: LLM уже управляет САПР

MCP (Model Context Protocol) — открытый протокол, через который Claude и другие LLM
вызывают инструменты внешних программ. Для САПР уже существует целая экосистема:

**Revit:**

- [mcp-servers-for-revit](https://github.com/mcp-servers-for-revit/mcp-servers-for-revit) —
  самый известный open-source проект (монорепозиторий, C#; прежние репозитории
  [revit-mcp](https://github.com/mcp-servers-for-revit/revit-mcp) и revit-mcp-plugin
  архивированы в его пользу в феврале 2026). MCP-сервер + плагин для самого Revit:
  естественно-языковые команды транслируются в вызовы Revit API к живой .rvt-модели.
  В той же организации — [mcp-server-for-revit-python](https://github.com/mcp-servers-for-revit/mcp-server-for-revit-python)
  (вариант на Python).
- [Demolinator/revit-mcp-server](https://github.com/Demolinator/revit-mcp-server) —
  48 инструментов через бесплатный pyRevit (Routes API): создание элементов
  (включая **`create_pipe`, `create_duct`, `create_mep_system`** — прямо то, что нужно для ВК),
  запросы, изменение, clash detection, спецификации (material takeoff), экспорт IFC.
  Revit 2024–2027, Python, лицензия MIT.
- [bimwright/rvt-mcp](https://github.com/bimwright/rvt-mcp) — MCP-шлюз для Revit 2022–2027.
- [PiggyAndrew/revit_mcp](https://github.com/PiggyAndrew/revit_mcp) — ещё одна реализация.
- **Официальный [Revit Public MCP Server от Autodesk](https://www.autodesk.com/blogs/aec/2026/06/17/revit-public-mcp-server/)**
  (июнь 2026, Revit 2027) — сам факт, что Autodesk выпустил официальный MCP-сервер,
  означает: «LLM управляет Revit» — это уже мейнстрим, а не хак энтузиастов.
- Учебные материалы: [pyRevit + MCP + Claude Code туториал](https://www.bimpure.com/blog/pyrevit-mcp-claude-code-tutorial),
  [обзор управления Revit естественным языком](https://bim-automation-studio.github.io/blog-revit-mcp-natural-language-control.html).

**AutoCAD / DWG:**

- [puran-water/autocad-mcp](https://github.com/puran-water/autocad-mcp) — исполнение AutoLISP
  через MCP, backend на ezdxf, символы P&ID. Работает даже с AutoCAD LT.
- [daobataotie/CAD-MCP](https://github.com/daobataotie/CAD-MCP) — управление CAD текстовыми
  командами (поддерживает AutoCAD-совместимые платформы).
- Обзор: [9 MCP-серверов для CAD (Snyk)](https://snyk.io/articles/9-mcp-servers-for-computer-aided-drafting-cad-with-ai/).

**Открытый стек IFC (без лицензий вообще):**

- [IfcOpenShell](https://github.com/ifcopenshell/ifcopenshell) — open-source библиотека (LGPL)
  для работы с IFC: полный парсинг IFC2x3/IFC4/IFC4x3, геометрическое ядро, Python API.
  Плюс Bonsai (бывш. BlenderBIM) — полноценный BIM-редактор внутри бесплатного Blender.
- [smartaec/ifcMCP](https://github.com/smartaec/ifcmcp) — MCP-сервер, через который LLM-агенты
  читают и изменяют IFC-файлы (ifcopenshell + FastMCP).
- [MCP4IFC (arXiv, 2025)](https://arxiv.org/html/2511.05533v1) — научная работа: связка
  LLM ↔ IFC через MCP-инструменты, геометрия обновляется в Blender через Bonsai.

**Renga (российский BIM):**

- Открытый COM API: нативные плагины на C++, .NET-плагины на C# (через interop,
  `RengaCOMAPI.tlb`), и — важно — **Python как официально документированный сценарий**
  внешней автоматизации (COM Local Server / ROT), а не сторонняя обёртка.
- Статья на Хабре [«Renga API: автоматизируем автоматизацию с помощью ИИ-агентов»](https://habr.com/ru/articles/1019272/) —
  прецедент подключения ИИ-агентов к Renga уже описан в рунете.
- Дополнительно: пакет узлов RengaDyn для Dynamo,
  [учебные курсы по Renga API](https://bim.vc/edu/courses/renga-instrumenty-avtomatizatsii-api-i-dynamo/).
  Готового MCP-сервера для Renga не найдено — **есть возможность стать первым** (это
  отдельная ценность проекта: MCP-обёртка над Renga COM API — задача на 1–2 недели).

### 3.2. Научные фреймворки: «текст → BIM-модель» уже опубликовано

- **[Text2BIM](https://github.com/dcy0577/Text2BIM)**
  ([arXiv:2408.08054](https://arxiv.org/abs/2408.08054), опубликовано в Journal of Computing
  in Civil Engineering) — мультиагентный LLM-фреймворк: четыре агента с разными ролями
  превращают текстовое описание в императивный код, вызывающий API BIM-платформы
  (Vectorworks), и генерируют редактируемую модель с планировками и семантикой.
  **Ключевая деталь: в контур встроен rule-based нормопроверщик** (интеграция с Solibri),
  который возвращает агентам список нарушений, и те итеративно чинят модель.
  Поддерживает Claude, GPT, Gemini. Лицензия MIT. Это самый близкий open-source аналог
  системы «Норникеля» — архитектуру можно брать за образец.
- [MCP4IFC](https://arxiv.org/html/2511.05533v1) — аналогичный подход на открытом стеке IFC.

### 3.3. Коммерческие продукты: доказательство, что MEP-разделы автоматизируются

- **[Augmenta](https://aecbytes.blog/2023/05/03/augmenta-automated-building-design-using-generative-ai/)** —
  генеративное ИИ-проектирование инженерных разделов в Revit. Уже построено
  [первое здание с ИИ-спроектированной электрикой](https://aecmag.com/mep/agentic-ai-accelerates-electrical-design/)
  (школа Mt. Hope Elementary, Мичиган): проектирование на 25 % быстрее, отходов материала
  на 15 % меньше, готовность к префабрикации на месяц раньше.
  **Сантехнический (plumbing) модуль — в альфе**: генерирует 3D-ответ на архитектурную
  модель, расставляя трубы и приборы. То есть ровно наша задача ВК решается коммерчески —
  подтверждение реализуемости.
- **[Hypar](https://hypar.io)** — генерация и анализ вариантов компоновок MEP-систем.
- **[HVAKR](https://aecmag.com/mep/hvakr-integrated-ai-hvac-design/)** — ИИ-проектирование ОВиК.
- **[MagiCAD Piping](https://www.magicad.com/applications/magicad-piping/)** — важный ориентир
  *без* ИИ: детерминированная автотрассировка труб, автоматические подключения, пересечения,
  изменения отметок, расчёты + база из 1 000 000+ BIM-объектов производителей.
  Урок: **трассировка — алгоритмическая задача, ей не нужна нейросеть**; ИИ нужен уровнем
  выше — понять ТЗ, выбрать концепцию, проверить нормы, оформить.
- Обзоры: [AI-инструменты для MEP 2026](https://www.novatr.com/blog/top-ai-tools-for-mep-engineers),
  [агентное будущее BIM (AEC Magazine)](https://aecmag.com/bim/the-agentic-future-of-bim/).

### 3.4. Российский контекст: нормы, проверка, платформы

- **Кейс «Норникеля»** — первая заявленная отраслевая система в РФ (см. §1).
- **Проверка документации по нормам как сервис уже существует**:
  [gostcheck.ru](https://gostcheck.ru/proverka-norm-ai) (проверка по СП/ГОСТ/СНиП с контролем
  актуальности), система «Цифровой стандарт» (RAG на строительной нормативке).
- **Критический опыт по RAG на нормах** (подробнее в §5):
  [Хабр: агентный поиск против галлюцинаций LLM на строительных нормах](https://habr.com/ru/articles/1059006/) —
  3000 слепых оценок; фронтир-модели «из коробки» массово выдумывают ссылки на пункты норм
  (порядка 120 выдуманных ссылок против 8 у той же модели с доменным агентным поисковым
  контуром поверх). [Опыт превращения нормативки в граф вместо векторной базы](https://www.pvsm.ru/ii/447515).
- **Платформы**: Renga (см. §3.1), nanoCAD (DWG-совместимый, есть .NET API),
  Model Studio CS. Обзор: [российские аналоги Revit](https://altecsystems.ru/rossijskie-analogi-revit/).
- **Источники нормативных текстов** для базы знаний: официальные публикации Минстроя,
  [files.stroyinf.ru](https://files.stroyinf.ru/) и аналогичные базы.

## 4. Почему ВК — правильный пилотный раздел

Сравнение разделов по пригодности для ИИ-автоматизации:

| Раздел | Формализуемость | Сложность геометрии | Цена ошибки | Мировой прогресс |
|---|---|---|---|---|
| **ВК** | Высокая (уклоны, диаметры, расходы — всё в таблицах СП) | Средняя (трубы с уклонами, стояки) | Средняя | Augmenta plumbing — альфа; MagiCAD автотрассирует |
| ЭОМ | Высокая | Низкая (лоткам не нужны уклоны) | Средняя | Дальше всех: здание уже построено |
| АР | Низкая (много «вкусовых» решений) | Высокая | Низкая | Text2BIM генерирует концепт, но рабочка далека |
| КЖ | Высокая, но через расчётные комплексы (ЛИРА/SCAD) | Средняя | **Максимальная** (несущие конструкции) | Осторожный прогресс |

Раздел ВК хорош тем, что почти каждое проектное решение выводится из норм и расчёта:

- **Нагрузки и расходы** — СП 30.13330 даёт секундные/часовые расходы по приборам и
  вероятностные формулы; это чистая математика.
- **Трассировка** — поиск пути на графе с ограничениями (уклоны самотёчной канализации,
  запрет прокладки над электрощитовыми, зоны прокладки) — классическая алгоритмическая задача.
- **Подбор диаметров** — гидравлический расчёт по таблицам/формулам (Шевелёв и др.).
- **Спецификация** — выборка из модели + сопоставление с каталогом производителя.
- **Текстовая часть (пояснительная записка)** — сильная сторона LLM.

Что усложняет: качество исходной АР-модели (если санприборы не расставлены или расставлены
«мебелью», а не семействами — нужен этап нормализации), координация с другими разделами,
узлы прохода через перекрытия.

## 5. Ключевой технический урок: как готовить нормы для ИИ

Самая частая ошибка (и самый важный вывод исследования): «загрузим PDF-ки СП в векторную
базу и подключим RAG». На строительных нормах это **не работает**:

1. **Галлюцинации ссылок.** Эксперимент с 3000 слепых оценок
  ([Хабр](https://habr.com/ru/articles/1059006/)): фронтир-LLM «из коробки» выдумывают
  номера пунктов СП десятками (~120 выдуманных ссылок), а та же модель с агентным
  поисковым контуром по реальной базе норм — единицы (~8). Модель обязана *искать и
  цитировать*, а не *вспоминать*.
2. **Таблицы и формулы теряются при векторизации.** Половина ценности СП 30.13330 — таблицы
  расходов и формулы. Их нужно извлекать не в текстовые чанки, а в **структурированные
  правила**: JSON/YAML-таблицы и исполняемый код расчётов, который агент вызывает как
  инструмент. Расход воды должен считать Python, а не языковая модель.
3. **Нормы — это граф, а не набор абзацев.** Пункты ссылаются друг на друга, документы
  отменяют и заменяют друг друга, у документов есть редакции и изменения
  ([опыт построения графа нормативки](https://www.pvsm.ru/ii/447515)). Актуальность
  редакций — отдельная задача (её решает, например, gostcheck.ru).

Итого правильная архитектура базы знаний — **трёхслойная**:
структурированные правила (код + таблицы) → граф документов и связей → полнотекстовый
агентный поиск с обязательным цитированием. Подробно — в
[docs/02-arhitektura.md](02-arhitektura.md).

## 6. Вывод исследования

1. **Технически задача решаема на уровне L3** («черновик раздела ВК по АР-модели и ТЗ,
   инженер проверяет») — все компоненты существуют в open-source, коммерческие аналоги
   (Augmenta) подтверждают жизнеспособность, «Норникель» подтверждает применимость в РФ.
2. **Управление САПР через ИИ (L1) доступно уже сегодня без программирования** —
   поставить revit-mcp и попробовать можно за вечер.
3. **Главная интеллектуальная работа проекта** — не «подключить нейросеть», а:
   (а) превратить СП 30.13330 в структурированные правила и расчётный код;
   (б) собрать детерминированный трассировщик;
   (в) выстроить мультиагентный контур с нормопроверкой, по образцу Text2BIM.
4. **Ниша не занята**: MCP-сервера для Renga не существует, открытой системы «раздел ВК
   по нормам РФ» не существует. Проект имеет самостоятельную ценность для всего рынка РФ.
