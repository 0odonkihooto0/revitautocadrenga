# Журнал решений

> Ключевые решения проекта в формате ADR-lite. Новые записи — сверху.
> Формат: `## ГГГГ-ММ-ДД — Название`, затем «Решение / Почему / Следствия».

## 2026-07-18 — Слой правил обязателен в контуре поиска по нормам

**Решение.** MCP-сервер norms_mcp отдаёт оба слоя базы знаний: BM25-поиск по полным
текстам (search_norms/get_clause) и YAML-правила слоя 1 (list_rules/get_rule); промпт
агента обязан предпочитать слой правил для чисел и формул.

**Почему.** Первая валидация (эксперимент 01): только полнотекст — 22/30 (73 %),
потому что md-конвертация теряет формулы и знаки сравнения; с подключённым слоем
правил — 30/30 (100 %). Ни одной выдуманной ссылки в обеих итерациях.

**Следствия.** Критерий этапа 1 (≥ 90 %) достигнут. Оцифровка новых таблиц/формул —
прямая инвестиция в качество ответов; вопросы валидации должны быть однозначны
(после добавления СП 31/32 вопросы «про канализацию вообще» стали двусмысленными).

## 2026-07-18 — СП 32: используем консолидированный текст с изм. 1, 2

**Решение.** В norms/ лежит консолидированная редакция СП 32.13330.2018 с внесёнными
Изменениями № 1 и № 2 (файл sp_32.13330_s_izm_2.pdf, docs.cntd.ru); первоначально
добытый файл «СП 32.13330.pdf» — только текст Изменения № 2 — не используется.

**Почему.** Изменение № 2 массово излагает разделы «в новой редакции»: без
консолидации по нему нельзя восстановить действующий текст.

**Следствия.** При добавлении следующих документов сначала проверять, что PDF —
полный действующий текст, а не отдельное изменение (титул + колонтитулы середины).

## 2026-07-18 — Роли агентов: сначала инструменты, сабагенты — по мере готовности

**Решение.** На этапе 2 роли (аналитик, расчётчик, компоновщик, нормоконтролёр,
документатор) исполняет сама сессия Claude Code поверх детерминированных модулей
(calc/trace, calc/normcheck, calc/sp30) с JSON-паспортом задачи как контрактом между
шагами. Первый выделенный сабагент — нормоконтролёр (.claude/agents/normokontroler.md).

**Почему.** Сабагент без готовых инструментов — это просто промпт; ценность появляется,
когда есть что вызывать (norms_mcp, чек-лист, расчёты). MVP прошёл сквозным контуром
без отдельной агентной обвязки (эксперимент 02).

**Следствия.** Остальные роли оформляются сабагентами по мере появления их
инструментов; проба нормоконтролёра — в следующей сессии (нужен перезапуск,
чтобы подхватился .mcp.json с norms).

## 2026-07-18 — Полные тексты СП коммитим в публичный репозиторий

**Решение.** Markdown-версии СП ядра ВК (30, 73, 31) лежат в norms/ репозитория;
PDF остаются только локально (C:\SNIPpars\downloads_faufcc). Решение принято
пользователем явно (сессия 2026-07-18) при осознанном риске: на текстах СП стоит
запрет Минстроя на воспроизведение и распространение без разрешения.

**Почему.** База знаний (слой 3 — полнотекстовый поиск) должна быть доступна и в
облачных сессиях, где локальных папок с СП нет; git — единственная переносимая память
проекта.

**Следствия.** При огласке претензий правообладателя тексты убираются из истории репо
(BFG/filter-repo) или репозиторий переводится в приватные. Значения в rules/ переносятся
только со сверкой по PDF — конвертация md местами неточна (формулы, слипшиеся слова).

## 2026-07-18 — Уклоны канализации: в СП 30.13330.2020 нет таблицы фиксированных уклонов

**Решение.** Слой правил кодирует то, что реально написано в СП 30.13330.2020: условие
самоочищения V·√(h/d) ≥ K (п. 19.1, формула (33)) с минимумами V ≥ 0,7 м/с и h/d ≥ 0,3,
нерасчётные участки — уклон 1/d; фиксированные уклоны — только частные случаи (п. 21.7).

**Почему.** Привычная таблица «Ду50 → 0,03» — из отменённого СНиП 2.04.01-85*; действующая
редакция требует расчёта. Пример YAML в docs/02-arhitektura.md §4 с «п. 8.7.3, табл. 8.3»
был иллюстрацией формата, а не реальной ссылкой — реальная оцифровка это подтвердила.

**Следствия.** Трассировщику этапа 2 нужен подбор уклона итерацией по гидравлике
(наполнение/скорость), а не lookup; см. rules/sp30/uklony_kanalizacii.yaml.

## 2026-07-17 — Память проекта живёт в git, а не в автопамяти Claude

**Решение.** Межсессионная память — файлы docs/status.md, docs/decisions.md,
docs/lessons.md; статус импортируется в CLAUDE.md и виден в каждой сессии.

**Почему.** Работа идёт в облачных сессиях Claude Code: контейнер эфемерный, встроенная
auto memory хранится вне репозитория и не переживает сессию.

**Следствия.** В конце значимой сессии агент обязан обновить status.md; решения и уроки
фиксируются в момент появления, а не «потом».

## 2026-07 — Мультиплатформенность: ядро не зависит от САПР

**Решение.** Ядро (агенты, база знаний, трассировщик, расчёты) платформонезависимо,
внутренний формат — IFC; САПР подключаются через MCP-адаптеры. Долгосрочная ставка —
Renga + открытый IFC-стек, Revit — референсная среда, пока доступна.

**Почему.** Autodesk ушёл из РФ (лицензионный риск); у Renga открытый API с официальной
поддержкой Python; IfcOpenShell бесплатен. Детали: docs/02-arhitektura.md §7,
docs/03-plan-realizacii.md «Ресурсы».

**Следствия.** renga-mcp предстоит написать самим (ниша свободна); эксперименты этапа 0
ведутся параллельно на Revit и Renga.

## 2026-07 — Пилотный раздел — ВК

**Решение.** Первый автоматизируемый раздел — внутренние водоснабжение и канализация.

**Почему.** Максимальная формализуемость (расходы, уклоны, диаметры — таблицы
СП 30.13330), трассировка — алгоритмическая задача, умеренная цена ошибки; коммерческое
подтверждение — Augmenta plumbing. Сравнение разделов: docs/01-issledovanie.md §4.

**Следствия.** База знаний этапа 1 строится вокруг СП 30.13330.2020 и смежных документов;
тираж на другие разделы (ЭОМ, ОВ) — этап 4.
